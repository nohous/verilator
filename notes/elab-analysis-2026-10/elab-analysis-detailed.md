## 0. TL;DR

1. **Your diagnosis holds on today's master.** There is no convergence loop between name resolution (`V3LinkDot`), specialization (`V3Param`) and constant/width evaluation (`V3Width`/`V3Const`). `process()` is strictly sequential; the only worklist anywhere is `V3Param::processWorkQ`, and it drains once — nothing is ever re-queued after a dependency becomes known. Dependencies on other parameterized things are handled by *recursing into them on the spot* and by *six post-hoc relink passes* that patch pointers by name/origName and explicitly give up when ambiguous.
2. **Four of your six legal probe tests fail on master**, two of them with segfaults, one with an internal assertion, one with the exact specialization-identity bug your commit message named (`BusDependent__pib39c82ee` vs `BusDependent__W5` — same interface, specialized once via explicit pins, once via defaults, treated as different types). Reduced to ≤3-line repros, they are **four distinct bug classes** (§1), all in the "default of formal *B* needs a specialization whose pins are formal *A*" shape — the chicken-and-egg you described.
3. **Upstream has no test for that shape.** Its one test with a sibling-dependent class default (`t_class_param_comparator.v`) spells out both actuals and never exercises the default. Everything in this area is considered "supported"; no test is marked unsupported.
4. **The convergence sketch has the right abstraction and an unsound implementation.** Right: one binding fact per formal per reference, explicit actuals pre-published, defaults as dependent queries, environment published when all bindings are, class identity = full declaration-order tuple, SCC-at-quiescence for the cycle diagnostic. Wrong: fact identity is raw `AstRefDType*`/`AstDot*` pointers held across all of V3Param (works only because deletions were deferred and V3Broken disabled at the new boundary), the projection graph mutates RefDTypes mid-drain, classes specialized through the projection callback are never queued for body elaboration (the bug upstream fixed in #8440), perf is unmeasured and the per-reference default cloning is a real UVM-scale cost. Rebase: 40 of 72 hunks fail; the IfaceCapture part is obsolete. **It is a rewrite, not a rebase.**
5. **Someone upstream has been here.** `V3Param.cpp:1568`, `V3Width.cpp:1137/4084/9232`, `V3LinkDot.cpp:4784/6233` carry comments about a "DepGraph architecture" — all authored by **em2machine** in #7128 (March 2026). No DepGraph pass exists or ever existed in the tree; it is residue of a design that did not land. em2machine has 35 commits in this exact area since Dec 2025 and is the person to align with. wsnyder's review stance on #7128: *"This will need several review rounds… This is a pretty large commit."*
6. **Recommendation** (§5): lead with failing tests, not architecture. File the four repro classes as issues (they are crisp, 3 lines each, two are segfaults). Then the smallest credible PR: make `resolveDefaultParams` (V3Param.cpp:1818, already a fixpoint since #8175) evaluate dependent defaults *in the instance's environment* for value **and** type formals, with a proper "Parameter default dependency is circular" from an SCC/DFS. ~150 lines, no LinkDot change, no new pass, subsumes #8175/#8184/#8182 and fixes bug classes A and B below. Only after that is there a credible path to lifting the projection facts out of `DeferredResolverVisitor`.

### 2.8 LinkDot internals (`src/V3LinkDot.cpp`)
- **Three steps, no memory.** `VLinkDotStep {LDS_PRIMARY, LDS_PARAMED, LDS_SCOPED}` (V3LinkDot.h:28); every step constructs a *fresh* `LinkDotState` symbol graph, runs Find → FindIface → Param/Scope → Resolve (:6518-6544) and throws the symbol table away. **No symbol-table state survives between steps**; only AST pointers (`typedefp`, `classOrPackagep`, `varp`, `classOrPackageNodep`) and node replacements carry results forward. Once a RefDType's `::` operand is consumed it is **deleted** (:6219), so later passes can only work from `classOrPackagep` — the source chain is gone.
- **The only retry is a bounded revisit, not a fixpoint.** `revisitLater` (:3655-3659) records the module *by name*; the Resolve constructor (:6482-6503) iterates once, `std::move`s the map and re-iterates each listed module once. Anything deferred *during* the second round lands in the moved-from member and is **never processed**. `m_lastDeferredp == nodep->lhsp()` (:4144) propagates a deferral exactly one Dot level up. ## 3. Why the fixes keep coming — structural weaknesses

Since your branch's base (2026-07-10): **~60 commits** touch `V3LinkDot.cpp`/`V3Param.cpp`/`V3LinkDotIfaceCapture.*`, 30 of them V3Param; em2machine alone has 35 in this area since Dec 2025. `Changes` lines like *"Fix resolving default/non-default type parameters (#7171) (#7346) (#7380) (#7385) (#7398) (#7406)"* are the maintainers' view of the same thing.

1. **Identity is an eagerly computed string.** Anything folded late (pin order #8604, `Class#(P)::lparam` #7746/#7609/#7524, `$bits(type_param)` #7711, textual element types) yields a wrong or split name; nothing can later merge or rename clones. Bug class E.
2. **Destructive in-place folding on shared templates**, modules without a pristine copy, correctness by level order; `parameterizedTemplate`/`skipWidthForTemplateStruct`/seven Width guards are symptom suppressors (#7463, #8086, #7711). Bug class A.
3. **Specialization as a side effect outside the work list** (`resolveDotToTypedef`, `classTypeMatchesDefaultClone`, `deparamIfaceCellNow`, `specializeNestedIfaceCells`) from arbitrary call depths; #8440 was a clone created this way never being elaborated, fixed with a back-channel vector rather than a scheduler. Bug classes B, C (UAF inside the side-effecting walk).
4. **Link repair by name/origName heuristics after the fact** (§2.7) that explicitly give up when ambiguous.
5. **Two "defer" systems with no feedback and no Param↔LinkDot iteration** (§2.6, §2.8): LinkDot rebuilds its symbol table per step and retries at most once per step (deferrals during the retry are dropped), so a cross-module `::` dependency gets ≤4 attempts in the whole pipeline; anything first resolvable in `linkDotParamed` that affects elaboration is unreachable by construction. Bug class D's non-diagnosis.

## 4. `pr-elab-convergence` (a90b9b524) — review

**Shape.** `V3Elab` (1960 lines, new): `ElabFactVertex` on `V3Graph` with `State {WAITING, QUEUED, RESOLVED, MISSING, CYCLIC, BLOCKED}` (E:97-156); `ready()` = all in-edge sources RESOLVED; `drain()` worklist; `classifyQuiescence()` runs Pearce SCC over unresolved-defined edges (E:211-233). Four graphs: **bindings** (one `ElabBindingVertex` per (reference, formal), explicit actuals pre-published, defaults cloned+substituted per environment, `ElabMaterializationVertex` per reference; E:287-431, 740-995), **projections** (`C#(..)::T` types, alias typedefs, `C#(..)::M` members; E:1146-1423, alive across all of V3Param), **deferred params** (E:1086-1104), **substitution** (replaces the 1000-iteration loop at V3Param.cpp:1486; E:658-723). V3Param consumes a canonical declaration-order pin tuple (`elabBinding`/`elabDefault` flags on `AstPin`) and asserts `"Non-canonical elaboration binding tuple"`. Deleted from V3Param: `resolveDotToTypedef`, `resolveParamClassRefDType`, `classTypeMatchesDefaultClone`, `resolveDefaultParams`, `defaultsResolved`, `ParamClassRefDTypeRelinkVisitor`, the `visit(AstVar)` deferral heuristics, `finalizeDeferredParams` (−~700 lines of accreted logic — each with an upstream regression test behind it).

**Sound.** The abstraction (§0.4). Class identity as the full declaration-order tuple (what makes `DepValue#(.N(3))` ≡ `#(.N(3),.M(4))` ≡ `#(.M(4),.N(3))`). SCC-at-quiescence with one "Parameter default dependency is circular (IEEE 1800-2023 6.20.1)" per formal. Dependent-default semantics unified across module/interface/virtual-interface/class at the binding level (E:997-1028). `substituteParams` as a replacement for the #7411 loop. The test `t_class_param_dep_type.v` — valuable on its own; most of its cases are not in upstream's suite in any form.

**Not sound as written.**
- *Pointer identity as fact identity* across all of V3Param (`m_typeFactMap`/`m_memberProjectionMap`/`m_sourceMap`, E:1441-1444). Works only because 12 `deleteTree()` were turned into deferred `pushDeletep` and `dumpCheckGlobalTree("elab", …, false)` (E:1870) **disables V3Broken** at the new boundary — the one place dangling pointers would be caught. V3Const/V3Width called from `cellPinCleanup` free and replace nodes on their own schedule; a freed-and-reused address silently aliases an unrelated fact.
- *"Replacements only at convergence boundaries"* is true for the binding graph (materialize/recover after classification) but not the projection graph: `ElabProjectionVertex::resolveFact` (E:1197-1200) and `ElabAliasProjectionVertex::resolveFact` (E:1258-1259) write `typedefp`/`refDTypep`/`dtypep` on live RefDTypes **during `drain()`**; `commit()` runs per cell inside V3Param; `linkPinToFormal` renames pins before any convergence (E:782-792).
- Classes specialized via the projection callback (`cellDeparam` → `resolveDependentProjections(nodep, nodeDeparam)`) are **never queued** for body elaboration — the same bug upstream fixed in f6ff5b4cf (#8440).
- `tryResolve` returning false is a dead end (vertex back to WAITING, nothing re-enqueues; E:139-147) → spurious BLOCKED. `ElabDeferredParamVertex` publishes whenever `valuep` is non-null, not when constant (E:1044).
- Identity change only for classes: module/interface value pins still use the old "same as default → omit" path, so **bug class E is not fixed by the branch either**; and every class default now appears in generated names (affects `--hierarchical`, coverage, any `.out` with class names — none updated).
- Scaling: a vertex per formal per reference netlist-wide, each default `cloneTree`'d per reference (E:727), a pin per formal per reference persisted into the AST, multiple whole-tree collector passes; no benchmark. UVM designs have tens of thousands of class refs.
- Unmodeled/fragile: `elab()` runs before generate unrolling (facts inside dead generate bodies/templates, then patched by name); `defparam` (pins with `paramPath` treated as explicit bindings at elab time, dropped per instance later); generic interface ports/modports untouched.
- Diagnostics lose instance context (`t_param_circ_bad.out` change); MISSING/BLOCKED/CYCLIC projection facts emit nothing and defer to later passes' messages.

**Rebase reality.** Dry-run against master's files: **40 of 72 hunks fail**; V3Param.cpp grew 3511→3880 lines with offsets up to 368; the four failing V3Param hunks are the structural ones (`cellDeparam`, `nodeDeparamCommon`, `visit(AstVar)`); V3LinkDotIfaceCapture hunks all fail — #8492's ledger/`CaptureType::CLASS` removal already did that deletion (1053→550 lines). ## 5. Recommendation

The answer differs by goal; I've written both.

### 5.1 If the goal is upstream
Wilson's acceptance pattern in this area is unambiguous: 29 V3Param commits in 3 months, each 1-85 lines + a test; #7128 at ~2500 lines took Feb→Sep 2026 and "several review rounds"; the DepGraph it hinted at never landed. A 2900-line replacement of V3Param's core will not be reviewed. The route that works:

1. **Issues first, with the 3-line repros** (class A: `e5`, `e6`, `e8`, `a3`; class B: `v3`, `v5`; class C: `m9`; class D: `c3`; E: `t_interface_virtual_param` cut-down; F: `t_interface_virtual_nocell` cut-down). Two segfaults and two internal errors on legal 6.20.1 code are not arguable. Reference `t_class_param_comparator.v` to show the shape is untested. Tag em2machine.
2. **PR 1 — dependent defaults in the instance environment.** `resolveDefaultParams` (V3Param.cpp:1818-1934) already has a fixpoint over sibling references (#8175); extend it from type-only to value+type formals, evaluate each default's `ClassRefDType`/`ClassOrPackageRef` pins against the *materialized sibling pins* (clone default, substitute published actuals — exactly `ElabSubstituteVisitor`, E:513-548 / `substituteParams`), and when no progress, emit "Parameter default dependency is circular (IEEE 1800-2023 6.20.1): Parameter 'X' of 'Y'" from a DFS/SCC over the formals of *that one reference*. Tests: `t_class_param_dep_cycle_bad` + the class-A subset of `t_class_param_dep_type`. ~150 lines, one file, no LinkDot/AST changes. Fixes A and D, subsumes #8175/#8182/#8184.
3. **PR 2 — the UAF in `DeferredResolverVisitor`** (class C, also B's crash). Either collect Dots first and resolve after the walk, or make `resolveDotToTypedef` not delete pins the visitor still holds. Small, test-backed (`m9`, `v3`, `c3`), probably accepted within a week — and it's a crash fix, which gets priority.
4. **PR 3 — identity from folded values** (class E): in `nodeDeparamCommon`, compute "equal to default" after the default has been substituted/folded in the instance environment (reuse PR 1's substitution) instead of requiring a template `Const` (:1565). Test: your `t_interface_virtual_param` addition.
5. Only then, the structural argument: lift member/type projections out of `DeferredResolverVisitor` into a scheduled worklist inside V3Param (a `needs` set per pending specialization, clone-then-fold, identity assigned at the end). Make it against #7746's 15 tests, not against the July base. At that point `V3Elab`'s binding graph is the design document, not the patch.

### 5.2 If the goal is a compliant fork
Then the convergence design is the right long-term shape, but rebuild it on today's master rather than rebasing: keep `V3Elab.cpp`'s graph machinery, re-derive the V3Param integration against #7746/#8440/#8604's code, and fix the three implementation faults first — (i) fact identity by stable key (e.g. `(owner module, formal index, reference ordinal)` or an `AstNode::user` slot) instead of raw pointers, with V3Broken **on**; (ii) projection resolution producing an *answer* that is applied at the boundary, not written into live nodes during drain; (iii) every specialization created anywhere enqueued for body elaboration. Measure on a UVM testbench before and after. Carry upstream's #7746 tests as your regression floor — they encode semantics you must not lose.

### 5.3 Either way
- Run your `t_class_param_dep_type.v` split into one test per section; it currently hides ≥3 bugs behind one assertion.
- The interface identity bug (E) is independent of the class work and probably the easiest to sell: it breaks virtual-interface assignment on legal code.
- Coordinate with em2machine (`#7128`, `#7746`, `#8492`), who has clearly been circling a DepGraph and owns the IfaceCapture redesign.
